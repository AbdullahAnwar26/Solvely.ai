# Architecture Notes

## Adding an owned model and endpoint (AD-5)

1. Subclass `core.ownership.OwnedModel` (gives `owner`, `created_at`, `updated_at`). Keep its default manager: `objects` must stay an `OwnedManager`.
2. Never put `owner` in a serializer's writable fields; the owner is always `request.user`.
3. Serve it with `core.viewsets.OwnedModelViewSet`, setting `model = YourModel` (not `queryset`). It requires authentication, scopes every query through `for_user(request.user)`, returns the 404 `not_found` envelope for foreign or missing ids, and sets the owner on create/update.
4. In any other code path, fetch rows only via `YourModel.objects.for_user(user)`.
5. Register the endpoint in `apps/api/tests/isolation.py` with `register_owned_endpoint(model, url, make=..., create_payload=..., update_payload=...)`. The shared cross-user checks in `tests/test_ownership.py` then run against it; an unregistered concrete `OwnedModel` fails the guard test.
6. Account deletion (Story 1.5) relies on `on_delete=CASCADE` from `owner`; keep it.

Owned models are deleted by cascade when their user is deleted; any new FK to the user model must use `on_delete=CASCADE` (enforced by the FK guard in `tests/test_account_deletion.py`).

## Web app conventions (apps/web, packages/shared)

- **Workspace:** npm workspaces from the repo root (`apps/web`, `packages/shared`), Node >= 22.22. Versions are pinned exactly (`.npmrc` has `save-exact=true`); commit `package-lock.json`.
- **Commands (repo root):** `npm ci`, then `npm run lint`, `npm run typecheck`, `npm run test` (Vitest + Testing Library, jsdom), `npm run build`. `npm run dev` starts Vite on http://localhost:5173 and proxies `/api` to http://localhost:8000 (override with `API_URL`), so session and CSRF cookies stay same-origin.
- **TypeScript:** pinned to 5.9.3, `strict`. TypeScript 7 (and 6) are not yet supported by `typescript-eslint` (peer `<6.1.0`) or `openapi-typescript` (peer `^5.x`); revisit when both widen their ranges.
- **Tokens:** `apps/web/src/styles/tokens.css` mirrors DESIGN.md: `--color-*` (light and dark sets), `--font-*`, `--space-*`, `--radius-*`, `--motion-*`, `--elevation-*`. The dark set applies under `prefers-color-scheme: dark` unless `<html data-theme="light">`, and always under `data-theme="dark"`. Components use variables only; ESLint rejects hex colour literals in TS/TSX. Add any new colour to both sets.
- **Fonts:** self-hosted via `@fontsource` (imported in `src/styles/fonts.ts`), bundled by Vite with `font-display: swap`; no runtime third-party requests.
- **Shell:** `src/app/AppShell.tsx`. Layout mode follows EXPERIENCE.md breakpoints (`src/app/layoutMode.ts`): `docked` >= 1200px (collapsible, remembered in `localStorage` under `wt.sidebar.collapsed`), `rail` 768-1199px (icon rail, sheet on demand), `drawer` < 768px (top bar + drawer). Route components are `React.lazy` pages in `src/app/routes.tsx`. Base styles give every focusable a 2px `--color-focus` ring and drop all transitions/animations under `prefers-reduced-motion: reduce`.
- **API calls:** only through `src/api/client.ts` (`api.get("/api/v1/health/")` etc.). Paths, request bodies and responses are typed from `@solvely/shared`. It sends `credentials: "include"`, copies the `csrftoken` cookie into `X-CSRFToken` on POST/PUT/PATCH/DELETE, and throws `ApiError` (`status`, `code`, `message`, `retryable`, `request_id`, `fields`) for any non-2xx; a body without the error envelope becomes `code: "http_error"`, a network failure `code: "network_error"`. Aborts are re-thrown unchanged.
- **Regenerating API types:** start the API (`cd apps/api && .venv/Scripts/python manage.py runserver`), then `npm run gen:api` from the root. It fetches `GET /api/v1/schema/` (override the origin with `API_URL`) and rewrites `packages/shared/src/generated/api.ts`; commit the result. Output is deterministic, so a clean re-run must leave no diff. If an endpoint's response shows up as `undefined`/`never`, its drf-spectacular schema is missing a response serializer: fix it in the view.

## Auth screens and session (apps/web/src/auth)

- **Session source of truth:** `SessionProvider` (root route element in `src/app/routes.tsx`) calls `GET /api/v1/auth/me/` on load; 403 means signed out, any other failure shows a retry screen. State lives in memory only. The session itself is the HttpOnly Django cookie, so nothing auth-related (tokens, emails, passwords) is written to `localStorage`/`sessionStorage`. Read it with `useSession()`.
- **CSRF:** `authApi.ts` calls `GET /auth/csrf/` before an unsafe request whenever the `csrftoken` cookie is missing; `src/api/client.ts` echoes it in `X-CSRFToken`. New unsafe calls should go through a helper that primes the cookie first.
- **Guards (`guards.tsx`):** `RequireAuth` wraps the app shell and redirects signed-out visitors to `/sign-in`, remembering the target in router state (`from`). `RedirectIfSignedIn` wraps sign-in, sign-up and forgot-password and sends signed-in users to `from` (in-app paths only) or `/`. `/reset-password` only waits for the session check so a reset link works even when signed in. Sign out clears the remembered target.
- **Forms:** `FormParts.tsx` (`TextField`, `FormSummary`, `SubmitButton`) gives visible labels, `aria-invalid`/`aria-describedby`, and an error summary that takes focus on each failed submit. `formErrors.ts` maps `ApiError.fields` onto inputs; unknown server fields land in the summary.

## Theme and settings (apps/web/src/theme, src/pages)

- **Theme handling:** the Learner's choice (`system`, `light`, `dark`) is stored on `Profile.theme_preference` and saved with `PATCH /api/v1/auth/preferences/`. `ThemeProvider` (inside `SessionProvider`) applies it by setting `data-theme` on `<html>` for light/dark and removing it for system, so `tokens.css` and the OS setting decide live. A failed save reverts the choice and shows a message. A non-sensitive hint (`wt.theme`: `light|dark|system`, the only allowed `localStorage` key besides the sidebar one) is read by a tiny inline script in `index.html` before first paint to avoid a flash; the server value wins once the session loads, and storage failures are swallowed (server value is used).
- **Dialogs:** confirmation dialogs use the native `<dialog>` with `showModal()` (no library). The component is mounted only while open: focus moves in on mount, Escape closes, Tab is kept inside, and focus returns to the opener on unmount. jsdom lacks `showModal`, so `src/test/setup.ts` shims it.
- **Account deletion:** `POST /api/v1/auth/account/delete/` (body `{password}`); the old `DELETE` route is removed because spectacular emits no body for DELETE. On success the session ends and the guard redirects to `/sign-in` with an "account deleted" notice (router state).

## Lessons and the Board (apps/api/lessons, apps/web/src/lessons)

- **Lesson is the first real owned model.** `Lesson(OwnedModel)` has a UUID primary key, `title` (max `limits.LESSON_TITLE_MAX_LENGTH`, default "Untitled lesson") and `current_revision`. Endpoints under `/api/v1/lessons/`: `POST` (optional `title`), `GET /{id}/`, `GET /` (paginated, newest first); no update or delete yet (405). Creation is throttled per user (`limits.LESSON_CREATE_RATE`). A malformed id is a 404, like a foreign or missing one. `tests/isolation.py` registrations now declare which actions an endpoint serves (`actions=`), and ids are compared as strings so UUID keys work.
- **Revision 0 means the empty Board.** There is no `BoardRevision` table or Board payload yet (Story 2.3); `current_revision` starts at 0 and nothing changes it in 2.1. Board edits are not persisted and the UI shows no save indicator.
- **Excalidraw 0.18.1** (exact pin; peer range allows React 19, which we run). `lessons/Board.tsx` is the only importer of `@excalidraw/excalidraw` and its CSS, and `LessonPage` loads it with `React.lazy(() => import("./Board"))`, so the library is a separate chunk fetched only when a Lesson opens. The canvas background is `transparent`, so the `--color-board` token shows in both themes; the `theme` prop comes from `useResolvedTheme()` (the Learner's preference, or the OS setting for "system"). On unmount Excalidraw tears itself down; `Board` also clears the undo history it can reach through the imperative API.
- **Routes:** `/lessons/:lessonId` (lazy). "New lesson" is the primary button at the top of the sidebar/drawer (`NewLessonButton`); it posts, then navigates to the new Lesson, and failures show in the shell alert area.

## Board tools, origin tagging and self-hosted assets (apps/web/src/lessons)

- **Origin tagging (AD-3):** `originTag.ts` (`tagLearnerElements`) is pure and idempotent: it adds `customData.origin = "learner"` to live elements that have no `origin`, keeps every other `customData` key, never overwrites an existing origin (`ai` stays `ai`), skips deleted elements, bumps `version`/`versionNonce` on changed elements, and returns the same array when nothing changed. `Board` runs it from `onChange` and writes back with `updateScene({ elements, captureUpdate: CaptureUpdateAction.NEVER })`, so tagging adds no undo entry. The loop guard is the "same array back" check (the second `onChange` finds everything tagged), and tagging waits while `newElement`, `editingTextElement` or `multiElement` is set so an element is never touched mid-draw. Checked in Edge: one undo removes a freshly drawn rectangle and redo restores it still tagged.
- **Undo/redo finding:** the documented `ExcalidrawImperativeAPI` (0.18.1) exposes `history.clear()` only, no undo or redo method. The app therefore does not add its own undo/redo buttons; Excalidraw's built-in buttons (visible at 1280, 820 and 390 px) and `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` are used. Revisit if a documented method appears (the board adapter would then own it).
- **View controls:** `BoardControls` (toolbar "Board view") offers zoom out, reset to 100% (shows the percentage), zoom in and fit to content, plus a polite live region that announces the settled zoom (300 ms debounce). Zoom is applied about the canvas centre with `updateScene` app state (`viewport.ts`); fit uses `scrollToContent` and is disabled on an empty Board. Zoom is clamped to 10%-3000%. Excalidraw's own footer also has zoom buttons, so two sets of zoom buttons exist; the app set is the one with the live region. Buttons are 32px on pointer devices and 44px on touch or below 768px.
- **Self-hosted assets:** `Board.tsx` sets `window.EXCALIDRAW_ASSET_PATH = "/excalidraw-assets/"` before the library loads. The fonts live in `apps/web/public/excalidraw-assets/fonts` (copied from `node_modules/@excalidraw/excalidraw/dist/prod/fonts`, about 500 KB). The 13 MB `Xiaolai` CJK font is deliberately left out; CJK text would fall back to the library's CDN default, so add it (or a subset) if CJK input becomes a requirement. When bumping Excalidraw, re-copy the folder. In Edge, drawing a rectangle, text, freehand and an arrow produced requests to `localhost:5173` only.
- **Touch:** in Edge with touch emulation at 390 px, pinch zoom, two-finger pan and one-finger freehand drawing all work on the canvas. A dev-mode React warning from Excalidraw's own `_App` ("update scheduled from inside an update function") appears at the phone size; it comes from the library, not app code.
- **Bundle:** the lazy Board chunk is still about 1.1 MB (345 KB gzip) and loads only on the Lesson route; no further splitting was done in this story.
